# PIV-Flow

**PIV-Flow: Verifying Recurrent Updates for Low-Light Optical Flow**

## Installation

Use Python 3.10+ and a mutually compatible PyTorch/torchvision pair. Install a
PyTorch build appropriate for your GPU first, following the official instructions:
https://pytorch.org/get-started/locally/

```bash
conda env create -f environment.yml
conda activate piv-flow
pip install -r requirements.txt
```

The default training configuration uses Linux and two CUDA GPUs. Single-GPU
training and CPU smoke tests are also supported. Windows multi-GPU uses Gloo.
On Jetson, install NVIDIA's matching torch/torchvision builds.

Optional worker detector and application dependencies:

```bash
pip install -r requirements-apps.txt
pip install git+https://github.com/JonathonLuiten/TrackEval.git
```

Run every command below from the `PIV-Flow/` repository root. Paths in YAML are
relative to that working directory. YAML inheritance paths are relative to the
configuration file itself. JSON configs also work.

## Data

Download FCDN and VBOF through their
[official project](https://github.com/mf-zhang/Optical-Flow-in-the-Dark).
Keep released data unchanged. Loaders consume JSONL pair manifests containing
relative file paths and acquisition metadata.

```bash
python -m tools.prepare_fcdn --root datasets/FCDN --index /path/to/fcdn_index.csv --output manifests --paper-protocol
python -m tools.prepare_vbof --index /path/to/vbof_index.csv --output manifests --paper-protocol
python -m tools.audit_data --root datasets/FCDN --manifests manifests/fcdn_train.jsonl manifests/fcdn_dev.jsonl manifests/fcdn_validation.jsonl --pixels
```

If FCDN uses FlyingChairs-compatible `*_img1`, `*_img2`, `*_flow.flo` names, use
`--official-split /path/to/chairs_split.txt` instead of `--index`. Other release
layouts use an explicit CSV index to map image pairs to references. The
`--paper-protocol` flag checks the dataset counts against the paper protocol.

See [dataset formats](docs/data.md) for CSV schemas, VBOF RGB processing, YOLOv8
worker annotations, tracking IDs, timestamps and belt calibration.

## Training

```bash
torchrun --standalone --nproc_per_node=2 train.py --config configs/piv_s.yaml --seed 17 --output runs/piv_s/seed_17
python train.py --config configs/piv_s.yaml --seed 17 --output runs/piv_s/seed_17
python train.py --config configs/piv_s.yaml --checkpoint runs/piv_s/seed_17/last.pth --output runs/piv_s/seed_17
```

Choose **one** launch mode. `batch_size` is global, before the two photometric
observations are formed. The default is 8 on either one GPU or two GPUs. Reduce
it in a local config if needed, and record that change with the experiment.
The schedule is 40k proposal warm-up, 20k frozen-proposal verifier initialization,
then 240k joint steps. Each phase has a separate warm-up/decay schedule. The RGB
control idles its frozen proposal during the verifier-only phase to preserve the
same proposal optimization opportunities as PIV-Flow.

```bash
python scripts/train_seeds.py --config configs/piv_s.yaml --seeds 17 43 89 --gpus 2 --output runs/piv_s
```

`last.pth` includes optimizer, AMP scaler, phase position, per-rank RNG state,
data epoch/cursor and configuration. Resume with the same world size, workers,
manifests and batch sizes. `best.pth` is selected by internal-development EPE
after verification is enabled. Official validation and VBOF do not select the
primary checkpoint. TensorBoard logs are in the run's `events/` directory.

Mixed-U is separate, camera-held-out adaptation:

```bash
torchrun --standalone --nproc_per_node=2 train_mixed.py --config configs/mixed_u.yaml --checkpoint runs/piv_s/seed_17/best.pth --output runs/mixed_u/canon
```

The supplied Mixed-U config holds out Canon. Make three corresponding config
overrides for Fuji, Nikon and Sony, using the manifests generated by
`prepare_vbof`. Utility targets remain FCDN-supervised; unlabeled real pairs only
supply teacher-student flow consistency.

## Evaluation and diagnostics

```bash
python evaluate.py --config configs/piv_s.yaml --checkpoint runs/piv_s/seed_17/best.pth --output outputs/piv_s/fcdn
python evaluate.py --config configs/piv_s.yaml --checkpoint runs/piv_s/seed_17/best.pth --root datasets/VBOF --manifest manifests/vbof_all.jsonl --output outputs/piv_s/vbof
python evaluate.py --config configs/piv_s.yaml --checkpoint runs/piv_s/seed_17/best.pth --policy median --output outputs/piv_s/median
python -m tools.diagnose --config configs/piv_s.yaml --checkpoint runs/piv_s/seed_17/best.pth --output outputs/diagnostics
```

`--save-flows` writes `.flo` files and their pair mapping. `--stress gain` or
`--stress noise` applies the locked stress conditions. `--iters 2`/`6` changes only
inference iterations. Diagnostics export per-pair/iteration rows; a frozen bank
can be supplied with `--bank-config configs/rgb_s.yaml --bank-checkpoint ...`.

See [experiments](docs/experiments.md) for ablations, seed aggregation, bootstrap,
external baseline prediction evaluation and profiler commands.

## Underground applications

Configure `configs/underground.yaml` or an inherited local config. Tracking and
conveyor processing use dense flow only; verifier scores never filter downstream
pixels. Accuracy evaluation processes every frame with its real timestamp.

```bash
python -m applications.run --config configs/underground.yaml --checkpoint runs/piv_s/seed_17/best.pth --task tracking --amp --output outputs/tracking
python -m applications.run --config configs/underground.yaml --checkpoint runs/piv_s/seed_17/best.pth --task conveyor --amp --output outputs/conveyor
```

See [application instructions](docs/applications.md) for detector training,
identity annotations, TrackEval, calibration and independent operational speed
references. Application profiling uses live detection, even when accuracy uses
a shared cache.
